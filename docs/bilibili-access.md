B 站访问保护
============

项目把目录同步、字幕获取、视频解析与下载、短链接解析、媒体代理和手动登录验证接入统一保护。目标是在出现限制时及时停止、减少重复请求，并隔离个人账号凭据。这些措施降低自动访问带来的风险，不能保证平台永远不限制请求或账号。

`core/bilibili_guard.py` 按实际出站请求计数，使用滚动时间窗口：

| 请求类别 | 最小请求间隔 | 每分钟上限 | 每小时上限 | 每 24 小时上限 |
| --- | --- | --- | --- | --- |
| B 站 API、网页与短链接 | 5 秒 | — | 120 次 | 600 次 |
| 字幕、图片、音视频 CDN | 0.25 秒 | 120 次 | 1,200 次 | 3,000 次 |

这些是本项目自行设置的保守额度，并非 B 站公开的安全阈值。不同接口、IP 和账号可能在更低请求量下受到限制。已获准发出的失败请求也消耗额度，所有用户、博主任务和工作进程共用额度；更换 Cookie 不会获得新额度。

保护状态默认保存到 `backend/db/bilibili_guard.db`，可通过 `BILIBILI_GUARD_PATH` 指定路径。进程内锁与进程间 `flock` 将请求准入、响应检查串行化，SQLite 保存请求时间和暂停状态。等待后会重新检查保护状态，避免已排队请求在风控发生后继续发出。服务重启不清空计数或暂停；状态文件不可用时停止联网。所有服务和子进程必须使用同一个状态文件及锁文件；不同机器或独立状态文件之间没有分布式限流。媒体响应流的后续读取不等于新的请求准入，分段或重定向产生的新请求仍需检查。

收到 HTTP 412、API HTTP 403，或 JSON 错误码 `-111 / -352 / -401 / -412 / -509 / -799` 时，只暂停对应功能：投稿列表、字幕、视频网页解析、视频信息 API、媒体资源与登录验证分别记录冷却。首次 10 分钟，24 小时内重复触发递增至 20、40、最多 60 分钟；24 小时仅为重复事件的观察窗口，不是禁止访问时长。账号 API 的 HTTP 429 对所有联网功能执行短时冷却；匿名 CDN 的 429 仅暂停对应资源。封面图片单独记录，按 2、4、8、最多 10 分钟退避，不暂停字幕 API。服务器提供 Retry-After 时以该时间作为最短等待。冷却期间其他未受限功能与缓存继续可用。到期不会主动创建请求，下一次用户操作可继续。更新 Cookie/重启不清除冷却。CDN 403 可能是签名链接过期，仅停止本次请求。旧版 24 小时状态按原触发时间迁移成短冷却，不重新起算。

目录同步每次最多读取 20 页（600 条），达到上限后保存页码与已有结果并暂停。手动继续从断点恢复，仍遵守全局额度。风控、预算用尽或保护拦截均不自动重试。尚未取得页面时的普通网络故障最多退避重试两次，分别等待 30 秒和 120 秒；已取得页面进度后暂停并保留断点。yt-dlp 的内部自动重试已关闭，分段下载并发限制为 1。风控后不切换备用接口、不轮换设备标识、不更换账号继续尝试。

保存在通用配置中的 B 站 Cookie 默认仅用于必要的登录 API：`nav`、`web-interface/view`、`player/pagelist`、`space/wbi/arc/search`、`player/v2`、`player/wbi/v2`、`dm/view`。普通网页和 CDN 默认匿名。`BILIBILI_USE_ACCOUNT_COOKIE=false` 可完全关闭自动使用账号；`BILIBILI_COOKIE_SCOPE=all` 可由管理员显式扩至 B 站网页请求，但并非默认。所有凭据仅通过 HTTPS 发送，不发往 CDN。yt-dlp 每跳重新计算凭据范围，同域跳至非必要接口也移除 Cookie，禁止 HTTPS 降级；元数据模式的 Cookie 文件不持久化登录凭据。

目录和字幕的成功 JSON 元数据短期缓存 2 分钟，最多 128 条，按请求参数和凭据区分，避免短期重复请求；缓存命中无需联网，即使处于冷却仍可使用。失败和风控响应不缓存。登录验证始终执行受限的实时检查。

yt-dlp 对公开视频不统一要求 Cookie，部分字幕、投稿列表或有权限限制的内容需要登录。仅支持受保护的普通 HTTP(S)/DASH 下载；直播/HLS或外部下载器会停止，防止绕过访问保护。本地合并和转码仍可使用 FFmpeg。

`/x/web-interface/nav` 返回 `code=0` 且 `isLogin=true` 只能确认该次请求的登录态有效，不能证明账号所有功能均未受限，也不能推断投稿目录等其他接口一定可用。应在官方客户端查看账号通知和实际功能状态。

访问暂停期间，可继续查阅项目已有学习资料与缓存，或在 B 站官方客户端观看。自有或已获授权的字幕文本可作为后续离线处理方案；当前项目没有字幕文本上传或粘贴导入入口，不能将这一方案视为已经提供的功能。

多个项目共用同一个账号时，请求量会叠加；本项目的额度不包含其他应用的请求。

工作台入口通过 metadata_only 读取已有视频信息缓存和同步目录；未缓存的分 P 使用视频信息 API，不为获取字幕先抓视频网页。播放/下载地址单独解析，不作为打开工作台的前提。


字幕接口使用官方 WBI 签名，签名素材按凭据缓存 30 分钟（登录验证仍实时请求）。并发相同 JSON 请求合并；手动重新获取跳过该次字幕接口及正文缓存，保留全局限速。封面缓存一小时，最多 256 条/32 MiB，失败不缓存，浏览器也可复用一小时。

新字幕保存 BV、CID、字幕轨道、取得时间和文本 SHA256；读取时校验来源标识、内容摘要及所选分 P 时长。历史缺少来源证明的记录标记为 legacy_unverified，明确不一致的字幕停止展示和复用，相关学习资料标记过期。该校验不能替代内容语义核验。批量字幕网络操作在工作线程执行，避免阻塞服务事件循环。


2026-11-16 最终验收：后端 472 项、前端 153 项通过，构建成功。浏览器验证 BV1mvnz65EsP 的 318 段已存字幕，以及此前被封面 429 阻断的 BV1fFpw68EnB（首次获取 830 段、约 10.6 秒），字幕来源信息成功落库。该耗时为单条实际任务，不能作为所有视频的性能承诺。

## 评审后补充的边界处理

显式刷新与普通请求并发时，较早开始的请求不能覆盖刷新后的缓存；同一资源的在途请求合并，并为调用方保留独立的响应读取状态。缓存命中不消耗访问额度。

签名素材复用与登录态验证分开：签名素材缓存 30 分钟，目录同步的登录校验和管理员主动验证始终执行实时、受保护请求。账号 API 返回 429 时保留全局保护；图片 CDN 429 不暂停字幕。`Retry-After` 支持秒数和 HTTP 日期，非有限数字忽略。

字幕地址只接受 HTTPS 的 B 站/hdslb 域名及默认 HTTPS 端口，不接受嵌入凭据。可识别的 aid+cid+hash 路径必须与请求一致；不透明路径不能据此证明身份。负时间、结束早于开始、NaN/Infinity、损坏来源记录和明确超出当前分 P 的时间轴均停止使用。基础视频链接按 P1 校验，旧文本字幕也检查已有时间戳。来源摘要用于发现内容与来源记录不一致，不能证明语义一定正确。

工作台优先读取轻量元数据，切换到下载页再按需获取下载格式；旧解析和旧任务事件不得覆盖当前视频。登录失效停止任务事件重连，暂时网络故障使用有上限的退避。
